이미지는 그림이 아니라 '숫자 덩어리'다

컴퓨터는 그림을 볼 수 없습니다. 컴퓨터가 다루는 이미지는 숫자를 격자 모양으로 늘어놓은 것, 즉 수학의 행렬과 텐서입니다. 이 사실 하나를 받아들이면 "이미지를 밝게 한다 / 회전시킨다 / 흐리게 한다"가 전부 우리가 배운 수 연산과 행렬 연산으로 설명됩니다.

직접 확인해 보세요 — 그림과 숫자는 같은 것입니다

아래는 16 × 16 크기의 흑백 이미지입니다. 버튼을 눌러 그림 ↔ 숫자를 전환하고, 칸 위에 마우스를 올려 보세요. 각 칸의 값은 0(검정)부터 255(흰색)까지의 정수입니다.

밝기 더하기 b 0
칸 위에 마우스를 올려 보세요.

밝기 슬라이더는 모든 칸에 같은 수 b를 더합니다. 즉 새 값 = 원래 값 + b. 이것이 예제 2에서 배울 화소값 변환의 가장 단순한 형태이고, 수학적으로는 행렬의 스칼라 덧셈입니다. 값이 0보다 작아지거나 255를 넘으면 잘라내는데(clipping) 이때 정보가 사라집니다.

rank수학 용어이미지에서의 의미TensorFlow shape 예시

44차 텐서이미지 여러 장(배치) — 딥러닝 입력 형태(32, 256, 256, 3)

왜 딥러닝은 항상 4차원을 쓸까? 신경망은 이미지를 한 장씩이 아니라 한 묶음(batch)씩 처리합니다. 그래서 맨 앞에 "몇 장인가"를 뜻하는 축이 하나 더 붙습니다. (N, H, W, C) — 이 순서를 NHWC라고 부르며 TensorFlow의 기본 형식입니다.

예제 2 · 화소값 변환 — 모든 픽셀에 같은 함수 적용하기

  

    
학습 목표 — 밝기·대비·반전·흑백·이진화가 전부 일차함수와 내적이라는 것을 확인한다. 픽셀의 위치는 그대로 두고 값만 바꾸는 변환이다.

  


  
y = clip( a · (x − 0.5) + 0.5 + b ,  0,  1 )
    a = 대비(기울기) · b = 밝기(y절편 이동) · clip = 0~1 범위 밖을 잘라내기

  
왜 0.5를 빼고 다시 더할까요? 그냥 a·x를 하면 이미지 전체가 밝아지면서 대비가 커집니다. 회색(0.5)을 기준으로 늘려야 밝은 곳은 더 밝게, 어두운 곳은 더 어둡게라는 진짜 대비 조절이 됩니다. 즉 중심을 0.5로 옮겨 놓고 늘린 뒤 되돌리는 것입니다.

예제 3 · 기하 변환 — 행렬로 이미지를 돌리고 키우기

  

    
학습 목표 — 회전·확대·이동이 2×2 행렬과 동차좌표 3×3 행렬의 곱임을 확인한다. 예제 2와 반대로, 픽셀의 값은 그대로 두고 위치만 바꾸는 변환이다.

  


  

    

      
회전 · 확대 : 2 × 2 행렬

      
R(θ) = [ cosθ  −sinθ ;  sinθ   cosθ ]    S(s) = [ s  0 ;  0  s ]

      
문제는 평행이동입니다. 이동은 (x+tx, y+ty)인데 이건 2×2 행렬 곱으로 표현할 수 없습니다. 곱셈만으로는 덧셈을 만들 수 없으니까요.

    

    

      
해결책 : 동차좌표 (homogeneous coordinates)

      
좌표 뒤에 1을 하나 붙여 (x, y, 1)로 만들면, 3×3 행렬의 마지막 열이 그대로 평행이동이 됩니다. 이제 회전·확대·이동을 전부 행렬 곱 하나로 합칠 수 있습니다.

      
M = T · R · S   →   (x', y', 1)ᵀ = M (x, y, 1)ᵀ

    

  


  
실습 도구 — 변환 행렬 실험실

  
슬라이더를 움직이면 행렬의 숫자가 실시간으로 바뀌고 이미지가 따라 변합니다. 아래에는 점 하나가 실제로 어떻게 계산되는지 곱셈 과정이 그대로 나옵니다.

  

    

      
회전 θ 30°

      
확대 s 1.00

      
tx 0

      
ty 0

      
    

    

      
원본

      
M 을 적용한 결과

      

        
변환 행렬 M = T · R · S

        

        

      

    

  


  

    
중요한 구현 요령 — 역방향 매핑(inverse mapping)

    
원본 픽셀을 하나씩 새 위치로 보내면(정방향) 결과 이미지에 구멍이 숭숭 뚫립니다. 회전하면 정수 좌표가 정수로 안 떨어지기 때문이죠. 그래서 실제로는 반대로 합니다: 결과 이미지의 각 칸에 서서, 역행렬 M⁻¹을 곱해 "이 자리에 올 원본 픽셀은 어디였나"를 물어봅니다. 그러면 빈칸이 생기지 않습니다. 코드의 tf.linalg.inv(M)이 바로 그 부분입니다.

심화 · 합성곱 — 3×3 행렬 하나로 이미지의 특징 뽑아내기

  

    
지금까지는 픽셀 하나만 보고 바꿨습니다(예제 2). 이제 주변 이웃 픽셀까지 함께 보고 계산합니다. 3×3 작은 행렬(커널 또는 필터)을 이미지 위에서 한 칸씩 미끄러뜨리며 겹치는 9개 값과 곱해서 더하는 것 — 이것이 합성곱(convolution)이고, CNN이라는 이름의 그 'C'입니다.
